# KeySender

Небольшое portable-приложение для Windows, которое вводит сценарии в активное окно с помощью клавиатурных событий Windows `SendInput`.

## Возможности

- WPF-интерфейс на русском языке.
- Начальная задержка перед запуском и интервал между клавишами.
- Отдельная задержка после Enter, случайный интервал между символами и до 1000 повторов сценария.
- Keyboard Mode с отправкой клавиатурных событий; Clipboard Mode для быстрого ввода текстовых блоков.
- Команды клавиш, сочетания с `CTRL`, `SHIFT`, `ALT`, `WIN` и паузы `{WAIT N}`.
- Кнопка STOP и глобальная аварийная клавиша F8.
- Ctrl+Enter запускает сценарий, когда активно окно KeySender.
- Открытие и сохранение сценариев `.kscript`, список последних десяти файлов.
- Настройки сохраняются в `%APPDATA%\KeySender\settings.json`.

Программа не записывает клавиатуру или мышь, не выполняет команды самостоятельно, не обращается к Интернету и не ведёт журнал введённого текста.

## Требования

- Windows 10 или Windows 11 x64.
- .NET 8 SDK для сборки. Опубликованную self-contained версию можно запускать без установленного .NET Runtime.

## Сборка и запуск

Откройте `KeySender.sln` в Visual Studio 2022 с компонентом .NET Desktop Development или выполните из корня репозитория:

```powershell
dotnet run --project .\src\KeySender.csproj
```

Self-contained single-file публикация для Windows x64:

```powershell
dotnet publish .\src\KeySender.csproj -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true `
  -p:DebugType=None -p:DebugSymbols=false `
  -o .\publish
```

Исполняемый файл будет находиться в `publish\KeySender.exe`.

## Синтаксис сценариев

Обычный текст печатается в активное окно. Переносы строк по умолчанию не нажимают Enter. Для перехода на новую строку в целевом приложении используйте `{ENTER}`. Опция «Перенос строки = Enter» включает преобразование переносов редактора в нажатия Enter.

Поддерживаются команды:

```text
{ENTER} {TAB} {ESC} {BACKSPACE} {DELETE} {SPACE}
{UP} {DOWN} {LEFT} {RIGHT} {HOME} {END} {PGUP} {PGDN} {INSERT}
{F1} … {F24}
{CTRL+C} {CTRL+SHIFT+ESC} {ALT+F4} {WIN+R}
{WAIT 1000}
```

Пауза принимает значение от 0 до 3 600 000 мс. Регистр команд не важен.

Блок `{TEXT}` … `{/TEXT}` вводит содержимое как текст, не разбирая команды внутри; переносы строк внутри блока сохраняются как Enter. Для буквальных фигурных скобок используйте `{{}` для `{` и `{}}` для `}`.

После `{ENTER}` KeySender ждёт указанное в настройках время (по умолчанию 100 мс). Случайный интервал можно включить отдельно и задать диапазон. Повтор сценария ограничен 1–1000 разами.

Пример:

```text
sudo apt update
{ENTER}
{WAIT 2000}
sudo apt full-upgrade -y
{ENTER}
```

Примеры сочетаний и сценариев:

```text
{WIN+R}
{WAIT 500}
cmd
{ENTER}
{WAIT 1000}
ipconfig
{ENTER}
```

```text
{CTRL+L}
https://example.com
{ENTER}
```

```text
ping 8.8.8.8
{ENTER}
{WAIT 5000}
{CTRL+C}
```

```text
root
{ENTER}
{WAIT 500}
mypassword
{ENTER}
{WAIT 1500}
ip a
{ENTER}
```

## Использование

1. Вставьте или откройте сценарий.
2. Выберите задержку и режим ввода.
3. Нажмите PLAY и переключитесь на целевое окно до окончания обратного отсчёта.
4. Нажмите STOP или F8, чтобы прервать ввод.

При включённой настройке окно сворачивается после PLAY. Приложение отправляет ввод только в текущее активное окно и не активирует окна самостоятельно.

## Ограничения

- Windows может ограничивать `SendInput` при вводе в приложение, запущенное с более высокими правами (UIPI).
- Некоторые удалённые консоли и приложения по-разному обрабатывают синтетические клавиатурные события.
- Clipboard Mode временно помещает текстовый блок в системный буфер обмена и по возможности восстанавливает его прежнее содержимое.
- Отправка клавиш не гарантирует, что целевое окно успеет обработать ввод: при необходимости добавляйте `{WAIT N}`.
- Keyboard Mode для символов, доступных в раскладке активного целевого окна, преобразует символы в Virtual Key и Shift. Символы, отсутствующие в раскладке, отправляются через Unicode-ввод Windows; совместимость такого ввода зависит от удалённой консоли. Clipboard Mode полностью сохраняет Unicode.

## Проверки

Локальные проверки парсера и исполнителя без дополнительных NuGet-зависимостей:

```powershell
dotnet run --project .\tests\KeySender.SpecChecks\KeySender.SpecChecks.csproj
```

Реальную отправку `SendInput` можно проверить интерактивно: запустите ту же команду с `-- --input-smoke` и щёлкните поле тестового окна. Оно проверяет английский и русский текст, пунктуацию с Shift и Ctrl+A:

```powershell
dotnet run --project .\tests\KeySender.SpecChecks\KeySender.SpecChecks.csproj -- --input-smoke
```

Проверка регистрации аварийного F8 и отмены сценария через сообщение `WM_HOTKEY`:

```powershell
dotnet run --project .\tests\KeySender.SpecChecks\KeySender.SpecChecks.csproj -- --hotkey-smoke
```

Для проверки физического нажатия F8 запустите длинный сценарий в KeySender и нажмите F8, пока приложение неактивно.
